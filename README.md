# RouteSIM

Веб-приложение для анализа, моделирования и проектирования маршрутных сетей общественного транспорта для городских поселений, решающее типовые задачи проектировщика маршрутных сетей - анализирует уровень обслуживания в существующем положении и проектных сценариях, оценивает соответствие транспортного предложения спросу на услуги общественного транспорта.

## Функционал приложения

- Подготовка и редактирование транспортной сети на карте.
- Оценка доступности общественного транспорта и сравнение вариантов обслуживания.
- Анализ пассажиропотоков, загрузки и дублирования маршрутов.
- Восстановление и прогнозирование пассажирского спроса.

Последовательность действий в RouteSIM: создание проекта (один вариант/сценарий существующего или прогнозного состояния), загрузка исходных данных, настройка расчета, ознакомление с результатами в форме итоговых сводок и интегральных показателей, таблиц, картограмм и графиков, выгрузка файлов с результатами расчета. Загрузка и сохранение массивов данных производится в формате CSV с разделителем `;` и кодировке UTF-8.

## Модули

| Модуль | Назначение |
| --- | --- |
| Проектирование сети (GEO) | Просмотр и редактирование геометрии и атрибутов объектов маршрутной сети на карте. |
| Уровень обслуживания (LOS) | Расчет времени, скорости и дальности поездок, пересадок и пешеходной доступности; обобщение показателей по остановкам, кластерам и транспортным районам. |
| Эффективность маршрутов (EFF) | Анализ дублирования маршрутов, пассажиропотоков, загрузки участков и использования провозной способности. |
| Восстановление матрицы корреспонденций (DEMAND) | Преобразование районной матрицы спроса в остановочную с учетом транспортного обслуживания и возможностью маршрутной калибровки. **Экспериментальный модуль.** |
| Прогноз спроса (FORECAST) | Прогноз матриц корреспонденций для новых территорий и существующих районов с калибровкой и диагностикой модели. **Экспериментальный модуль.** |

Серверная часть написана на Python и Flask, интерфейс использует Jinja-шаблоны. Метаданные проектов и учетные записи хранятся в SQLite, входные файлы и результаты в файловой системе. Для расчетов используются библиотеки NumPy, pandas, SciPy, sklearn, GeoPandas, NetworkX.  

## Запуск через venv

Требуется Python 3.13 (для Windows - Python должен быть прописан в PATH, это базовая опция при установке) 
Команды выполняются из корня репозитория (в Windows зажмите shift и кликните правой кнопкой мышки на директорию с файлами, далее выберите "Открыть в Терминале", после этого должен запуститься PowerShell).

### Установка окружения и зависимостей
1. Установите виртуальное окружение:
```bash
python -m venv venv
```
2. Активируйте окружение:
```powershell
# Windows PowerShell
venv\Scripts\Activate.ps1
```
```bash
# Linux / macOS
source venv/bin/activate
```
3. Установите зависимости приложения:
```bash
python -m pip install --upgrade pip
python -m pip install -r source/requirements.txt
```
4. Инициируйте базу данных:
```bash
python base_init.py
```

### Запуск локального сервера RoutSIM:
1. Активируйте окружение (не требуется если после установки не был закрыт PowerShell)
```powershell
# Windows PowerShell
venv\Scripts\Activate.ps1
```
```bash
# Linux / macOS
source venv/bin/activate
```
2. Перейдите в папку с приложением и запустите приложение
```bash
cd app
python wsgi.py
```
3. Откройте приложение по ссылке [http://localhost:5000](http://localhost:5000).
4. По умолчанию создается 2 учетные записи:
- пользователь (логин: user, пароль: 1111)
- администратор пользователей (логин: cappower, пароль: 1111, endpoint: /letsrule/)

## Запуск через Docker
Требуются установленные Docker и Docker Compose, а также запущенный Docker Engine (при использовании Docker Desktop запустите Docker Desktop). Порт `5000` на компьютере должен быть свободен.
Все команды выполняются из корня репозитория, где находится `docker-compose.yml`.

Первая сборка и запуск (требуется доступ к интернету для загрузки базового образа и зависимостей):
```bash
docker compose up --build -d
```
При старте контейнера автоматически выполняется `base_init.py`, затем запускается Gunicorn. Приложение доступно по адресу [http://localhost:5000](http://localhost:5000).
Повторный запуск из уже собранного образа, без сборки и установки зависимостей (в том числе после `docker compose down`):
```bash
docker compose up --no-build -d
```
Проверка состояния контейнера:
```bash
docker compose ps
```
Просмотр журналов:
```bash
docker compose logs -f web
```
Чтобы выйти из просмотра журналов, нажмите `Ctrl+C`; контейнер продолжит работать.
Остановка без удаления контейнера:
```bash
docker compose stop
```
Запуск существующего остановленного контейнера:

```bash
docker compose start
```
Остановка и удаление контейнера:
```bash
docker compose down
```
После изменения кода, зависимостей или `app/.env` пересоберите образ и запустите приложение:
```bash
docker compose up --build -d
```
Обычный перезапуск контейнера не применяет изменения файлов проекта: они копируются в образ при сборке.

Compose устанавливает `SQLITE_PATH=data/routesim.db`. База данных, журналы и пользовательские файлы хранятся в именованных volumes и сохраняются после остановки контейнера. 
Для повторного использования тех же volumes сохраняйте имя проекта Compose: по умолчанию оно определяется именем каталога репозитория. Переименование каталога может привести к подключению новых пустых volumes.
Для удаления контейнера вместе с сохраненными данными выполните:
```bash
docker compose down -v
```
